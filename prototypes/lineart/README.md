# 第 0 階段：線稿轉換原型

驗證整個 APP 風險最大的部分：**照片能不能變成 2.5–5 歲小朋友塗得開心的著色圖**。

![比較圖](results/comparison.jpg)

## 做法

一般的「邊緣偵測」產生的線條常有缺口，油漆桶一點就漏色。這個原型改用 **「色塊分區」**：

1. **找主角並去背**：原型用 GrabCut 代替。APP 裡會用手機內建的主體偵測（Android ML Kit、iOS Vision），或讓小朋友 **用手指把東西圈起來**。
2. **自動裁切放大**：主角太小（例如火箭）時，會自動放大讓它填滿畫面。
3. **分成少數幾個色塊**：先平滑處理，再分群顏色，太小的色塊併進旁邊的色塊。和周圍顏色差很多的小色塊（眼睛、按鈕）會保留下來。
4. **在色塊交界畫線**：外框粗、內線細，線條有抗鋸齒。**每個區塊都一定是封閉的**，油漆桶一定填得滿。
5. **細節線**：補上長而明顯的邊緣（眼睛、杯緣），讓圖看得出是什麼。細節線不用封閉，塗色會自動繞過。
6. **可愛風格（不需要 AI）**：
   - 更圓滑的外形、更少色塊
   - 在最寬敞的區塊放上可愛的臉（眼睛、微笑、腮紅）
   - 貼紙風外框
   - 背景隨機放星星和愛心

輸出分成兩部分：

| 輸出 | 內容 | 用途 |
|---|---|---|
| `*_page.png` | 白底黑線著色圖 | 畫給小朋友塗 |
| region map | 每個區塊一個編號 | 油漆桶和「不出界」模式使用 |

## 目前結果（3 張公開樣本照片）

| 照片 | 真實・簡單 | 真實・普通 | 可愛 | 評估 |
|---|---|---|---|---|
| 咖啡杯（單純物體） | 11 區 | 14 區 | 13 區 | **可用**。杯子、杯緣、把手、盤子都看得出來；可愛風格效果最好 |
| 火箭（細長、背景雜亂） | 4 區 | 8 區 | 11 區 | **勉強**。去背成功，但太細長，塗色空間少 |
| 貓臉特寫（毛皮紋理） | 11 區 | 14 區 | 4 區 | **不理想**。眼睛、鼻子有出來，但色塊線條雜亂，看不太出是貓 |

**初步結論**
- **單純的物體**（杯子、玩具、水果、車子、花）用這個方法就可以，**免費、離線、在手機上就能處理**。
- **動物和特寫**需要更好的線稿方法。下一步要測試開源的線稿 ML 模型。
- **速度**：在伺服器 CPU 上每張約 0.6–3 秒（Python）。手機版改用 OpenCV 原生程式並調校後，預期可以維持在相近範圍，但要實測。

**已知問題**
- 金屬反光（湯匙）會產生雜亂的小線條。
- 主角被照片邊緣切到時，會出現一條直線。

## 下一步：需要真實照片

公開樣本只有 3 張，**需要用小朋友實際會拍的東西來測試**。請準備 10–20 張照片，例如：玩具、絨毛娃娃、水果、花、寵物、車子、餐點、公園的溜滑梯。

- **請避免拍到人臉**
- 傳送方式（任選）：
  - 直接在對話中附上
  - 上傳到 GitHub 的 `prototypes/lineart/photos/` 資料夾

## 自己執行

```bash
pip install -r requirements.txt
python run_samples.py                 # 使用內建樣本，結果輸出到 results/
python run_samples.py 照片資料夾/      # 使用自己的照片
python lineart.py 照片.jpg --style cute --rect 0.1 0.1 0.9 0.9
```

`--rect` 是主角的大概範圍（以照片比例表示：左、上、右、下）；主角填滿畫面時可以省略。
在照片資料夾放一個 `samples.json`，可以分別設定每張照片的範圍，以及要不要加可愛臉：

```json
{"dog.jpg": {"rect": [0.1, 0.1, 0.9, 0.95], "face": false}}
```

樣本照片來源：scikit-image 內建的公開授權樣本（coffee、chelsea、rocket）。
